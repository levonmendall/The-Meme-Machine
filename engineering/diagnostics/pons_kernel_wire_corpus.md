# Synthetic Pons native wire coverage

`isolated_native_pons_kernel_corpus.PonsKernelCorpus` is an offline provider
input, never an economic or financial authority. The default remains an empty
economic corpus. Explicit `economic=True` enables two fixed synthetic markets.
No captured production receipt, transaction, token, address or market state is
copied. Pinned deployment metadata, source ABIs and the verified compiler runtime
template supply the original native authentication contracts.

The first copied-main failure was a real fixture omission: native
`Preparation.begin()` requests four deployment codes, including `pons_deployer`,
where the initial fixture supplied three. Its headers also omitted the original
parser's required parent hash. The small conformance correction supplies all four
pins and coherent genesis/header linkage; it does not remove either native check.

The optional economic corpus supplies an ungraduated Current curve and a distinct
graduated Survivor token. Current gets eight buys, one sell, exact full receipts,
synthetic independent actors, reserves and 15-word factory records. All declared
compiled curve immutable references are filled consistently with those records.
The actual Current acquisition function performs its ordinary code/factory/log
authentication, original prospect and trajectory screens, 60-second canonical
window acquisition and receipt decoding before `CurrentHistory.remember()`.
The existing fixture age/reserve shape exercises these code paths; it does not
alter any current strategy rule or imply positive qualification.

Survivor receives an observed synthetic launch followed by an ordered
Initialize/PoolRegistered/PoolGraduated receipt and one later Swap. Original
`Preparation.authenticate_step()` proves the same native relationships and creates
the native PonsHistory candidate. The component test uses original
`Preparation.history_step()` and the bound native `Runtime._append_tape` reducer
to decode the Swap and append history. Its narrow history-owner facade does not
construct a financial book or prove a complete Runtime constructor/step lifecycle.
The copied-main harness must independently exercise that actual owner lifecycle.

RPC and Nitro share one immutable header model. At most 128 messages publish a
maximum of 63 successor blocks, one block per two half-second frames. Latest/head
RPC reads follow the published head and refuse future blocks. A reopened stream
keeps the same sequence/head instead of rewriting an old timestamp. The actual
Nitro WebSocket framing parser reads anonymous local socketpairs. The signature
marker is explicitly synthetic; external WebSocket/TLS and signature
authentication remain unexercised. A prematurely published future-dated economic
event still fails the unchanged native decoder.

Direct focused tests demonstrate native Current candidate creation, buy/sell
decoding and nine durable Current history rows, plus one native Survivor candidate
and authenticated Swap history. They also preserve missing deployment/header,
receipt-disagreement, future-event and unknown-method refusal. They exercise no
real provider, quota increase, financial genesis, allocation, fill, settlement,
held protection or production history. Parent sizing remains zero. The full
kernel run, nonprobe decoder/history process execution, source FULL/ACK binding,
complete pool universe, actual market workload, lambda/mu, retained restoration
and sustained capacity require their own receipts and are not established here.
