# Native source and history-delivery cohorts

This opt-in diagnostic component is separate from the deployed comparison candidate. Its predecessor is f00a7727d9f64926aa36e1044f854c5ed91df990. It does not change provider operations, intake queues, canonical writers, SQL, transaction boundaries, native strategy, funding or recovery authority. Set `MM_ECONOMIC_COHORT_DIAGNOSTICS=1` explicitly to collect it; the original supervisor forwards only the exact literal `1`. Other values select the unchanged default path. No production activation is performed by this component.

## The measured populations

The common `EconomicCohorts` reducer records unique **native decoder economic records within a finite cohort**, canonical post-COMMIT observations, complete commit-time candidate-history fanout, and verified consumer FULL-COMMIT plus canonical source ACK observations. These are four separate populations. `native_new` / `new_canonical` mean an insertion into the actual native canonical store, not a globally new market event after retention. Physical replay and repeated publication are not new economic identities inside the same cohort.

Pump's source interval contains BOTH original configured program feeds. The adapter uses the original filtered status/log join and original prepared economic records. Every admitted frame's full prepared-record identity/content/position census is retained independently from the arrivals callback. A source seal must match its expected count and sorted digest. Missing whole acquisition hooks cannot become an empty successful interval; genuine empty intervals require an explicit zero decoder census and a real post-COMMIT observation.

Eight linked produced blocks form a window. The next linked child sets its inclusive upper slot to child.slot-1, preserving authenticated skipped slots. Only actual original `IntervalProof` objects staged by the original canonical transaction can cover each program's whole interval. The adapter never supplies a proof to the native source or repairs a gap. Successive sealed windows must be adjacent. A reconnect, unsupported/non-separated path, missing timestamp, gap, conflict, contention or bound makes the measurement UNKNOWN. The original native reconnect/recovery continues unchanged; this diagnostic does not merge overlapping replay generations or certify a missing prospective interval.

## Actual commit and fanout seams

`commit_candidate_batch` stages metadata only for prepared, non-grouped, separated delivery with no enclosing transaction. Original `RollingHistory.store` / `store_many` report authenticated canonical identities, semantic content hash, original availability and actual insertion classification. Original canonical SQL and all original rollback/error paths remain intact. Staged observations publish only after the original outer transaction successfully exits. Nested transactions are unsupported rather than being mistaken for outer durability. Ordinary diagnostic errors latch UNKNOWN and cannot replace the original economic failure.

`CandidateLifecycle.queue_records` already iterates the complete `SELECT DISTINCT evidence_bindings` population for each record. The diagnostic adds no query. Each actual `emit_raw` return is included in a length-framed outbox-ID digest and count. A separate completed-iteration marker is emitted after that whole original iteration, even for zero fanout. The common reducer compares this marker with independently staged outbox IDs, original source-body hashes and consumer scopes. Omitting a fanout hook cannot turn a missing obligation into an apparent zero. The population is **bindings at each measured canonical commit**, not every future binding or all possible strategy work.

The only Pump ACK seam is after original `acknowledge` has checked source generation, unchanged original outbox body/hash and binding, genuine CandidateHistory source receipts, complete ACK order and exact compact canonical bytes/hash, and after original `acknowledge_rows` has COMMITted. Both regular delivery and cancellation drain use this same original function. Consumer-receipt time is retained source availability; it is not relabeled as completion time. A replay obligation already consumed before measurement is not guessed complete from a count or old ID; without a later genuine measured ACK it remains unresolved.

The common source seal freezes its expected economic population: new arrivals after a complete seal are refused, exact repeats remain idempotent, and final reconciliation rechecks the retained expected count/digest. No forgotten late callback can expand the authenticated source population while waiting for COMMIT/ACK.

## Head and clock evidence without another provider call

The existing CONTROL stream independently receives original FINALIZED block metadata and slot notifications. Immediately before its existing bounded queue, the adapter compares successive already-joined headers' exact slot/hash-to-parent linkage. A head is exposed only after its real linked child arrives. This is an **observed finalized linked header**, not a durable CONTROL receipt or an unseen external latest tip.

Each such observation retains actual blockTime seconds, original received wall time, local observation wall/monotonic clocks, and linked child coordinates. Each snapshot exports the original observation age, signed wall-minus-market age, and wall-versus-monotonic delta. It neither renews the original clocks nor clamps a wall jump into freshness. Source windows retain their actual first blockTime and linked-child blockTime as a separate matching cohort SHA. Missing, equal/coarse or nonmonotonic blockTime cannot provide a positive source duration by inference. BlockTime is a chain timestamp with seconds granularity; it is not a kernel creation timestamp or exact event latency. A blocked/replayed control feed remains visible through its real market and observation ages.

These fields permit a later acceptance reader to compare complete adjacent economic intervals, canonical and ACK completion, observed market lag and fresh head continuity using the same clocks. No request, quota or independent polling loop is added. If the existing authenticated stream cannot supply sufficient freshness for the final acceptance criterion, the remaining capability is a fixed paced governed head read under the original provider Budget/Governor, subject to separate design; this component does not silently execute it.

## Bounds, public export and UNKNOWN

The identity capacity covers a full original 8×2048-record batch plus the next full batch supplying its linked child; obligations allow two native fanouts per admitted identity before the byte bound. This changes no original intake, transaction or provider limit. The reducer admits at most eight active cohorts, 32,768 active identities, 65,536 tracked obligations and 8,192 seen cohort SHA values. A 32-MiB logical metadata charge accompanies these object-count bounds; it is not a measured Python RSS ceiling. Closed summaries retain only 16 scalar/count/digest rows, with explicit eviction count and a cumulative summary hash. Scope containers/counts are checked before iteration and native positions are bounded to signed 63-bit storage coordinates. The Pump adapter separately limits retained frames, eight windows, 32 proof intervals per scope/window, bounded source metadata and 16 source-clock summaries. It retains no raw transactions, logs or economic bodies and creates no second spool.

The original `native_streams` service-health row carries the source snapshot. The existing diagnostic collector already reads that exact indexed key; its fixed projection adds no SQL or provider operation. It copies only admitted fixed enums, finite numbers and SHA values, under a 24-KiB optional projection limit and original overall budgets. Private or inconsistent fields cannot escape via arbitrary dictionary copying. Overflow is UNKNOWN, never truncation presented as a complete census. Original default output remains unchanged when the opt-in field is absent.

Pons may use the same bounded identity/publication reducer, but its consumer contract is explicitly `PONS_CONSUMER_COMPLETION_UNESTABLISHED`. Solana-style `acknowledged` is rejected for Pons and source closure alone cannot finish it. Pons's actual configured-universe and Current/Survivor outcome adapters are a separately reviewed component. Their partial native history publications are not a whole-Pons arrival denominator or fake FULLACK.

## What this does not establish

`CLOSED_COHORT_RECONCILED` establishes this exact source-and-history-delivery reconciliation. It does not establish that Current/Survivor has evaluated every stored record, held-position protection, native readiness, history completion, financial permission, or sustained full-market capacity. Those downstream strategy frontiers and all configured Pons consumer outcomes remain necessary for an end-to-end rate claim. Original proof publication/coverage frontiers remain a separate population and original guard; a canonical-delivery ACK does not settle an outstanding proof. The public processing_stage explicitly excludes strategy and proof publication. The original two unknown callbacks and all prior recovery outcomes are unchanged.

A cohort's elapsed completion time is a latency measurement, not sustained service rate. Event availability may be learned after original acquisition backpressure; compare the actual authenticated block-time span and continuously observed finalized head to expose upstream lag. Continuous same-universe A/C and fanout/ACK, no gaps/overflow/missing samples, fresh clock/head relationships, and complete native consumer outcomes are required before computing a full-market lambda/mu verdict. The reducer deliberately exports no authoritative rate or PASS. Later acceptance can use these complete finite populations and clock evidence; it must not infer full speed from an empty local queue or provider usage.
