# Copied native process lifetime component

This component adds an explicit `native-landlock-abi6-x86_64-v1` copied-layout
path. The original no-argument namespace entry and default image builder stay
unchanged. It does not install Landlock/seccomp, launch providers or authorize a
financial operation. The separately owned fixed launcher must authenticate the
original image approval/build result and install the complete OS policy.

`image.build(..., profile=PROFILE)` adds one regular, mode-0500 static x86_64 ELF
at `runtime/bin/native-spawn` to the existing copied-image manifest. The helper
has no PT_INTERP, dynamic dependency, setuid bit, compiler dependency or runtime
argument selecting an executable. Its final bytes embed the absolute private
Python path. `PinnedNativeImage` checks those exact generated bytes and grants
that one inode EXECUTE; all source/dependency/loader checks still apply. Assembly
is retained in `native_spawn_shim_v1.S`; its 265-byte machine-code SHA256 is
`d14fe952caf0533b585a7755b877e77570d2635cedd2f0889cec002850393761`.

The explicit fixed entry reserves an internal CLOEXEC pipe at FD5/6 before any
resource tracker exists. FD5 is the read-only lifeline; only main retains
writer6. The common CPython `util.spawnv_passfds` adapter covers both real spawn
workers and the real resource tracker, preserves all legitimate original
passfds, adds5 and rejects collisions with authority3/4 and lifeline5/6. It runs
the original fork/exec on one retained spawning thread because Linux PDEATHSIG
belongs to the creating *thread*. Each handoff applies and restores the
submitting thread's exact signal mask, including CPython's tracker TERM/INT
startup mask.

Before Python, the helper verifies a FIFO/read-only FD5, refuses readable data,
HUP or error, captures ppid, arms SIGKILL PDEATHSIG, checks ppid and lifeline
again, closes5, and execs only its embedded Python. Lifeline EOF covers owner
death before the first getppid even without a PID1 assumption. Main and every
worker retain the fixed private `LD_LIBRARY_PATH`; the builder/policy still pin
the one real host PT_INTERP loader inode. An outer owned process-group supervisor
must retain physical descendant cleanup ownership and must reject nonzero
exits. This component does not independently prove that outer fence.

The native source registers the spawn scope before its first real decoder
submit. Its original cleanup order joins owner/delivery/history/decoder/
checkpoint, then stops and reaps the real tracker and joins the retained spawn
thread under the existing 65-second source fence. An earlier failed close keeps
the spawning thread alive. Fixed entry treats an unjoined tracker as the typed
fatal drain handoff and skips every cache/channel/resource close until owned
process termination. No second grace period is introduced.

The explicit main installs genuine own-process liveness from exactly its
`/proc/self/stat` and shared boot-id file. Foreign PID identities and denied,
stale or forked observations remain UNKNOWN, and native Plane recovery rolls
back instead of reclaiming those claims. Pure decoder/history workers install
only the deny-financial initializer and need no foreign or own proc-file grant.

Focused fixtures cover static helper bytes/ELF, exact manifest/EXEC rule,
negative lifelines, pre-first-instruction owner death, actual copied CPython
2+1 spawn workers, tracker and mask inheritance, short-lived submitting thread,
owner death during Python import, partial constructor FD cleanup and unknown
native ownership preservation. These are offline component checks. Actual
Landlock application to this Python image, private-work syscall closure,
authenticated live sizing/provider integration, all four native consumer
throughput and financial PAPER readiness remain separate acceptance steps.
