# Native Pons Survivor requests and committed decisions

This unselected future slice extends reviewed composition `8e8132f4`. It records
actual native work stages without changing provider calls, policy, native five
second freshness, fair selection, financial authority or transaction boundaries.
The separate reviewed Plane performance component `e0a95ec2` must still survive
integration; it is not an ancestor of this future branch.

The existing second `PonsHistory.rows()` traversal in Survivor supplies a finite
turn inventory. With a genuine private `NativePonsOwnerContext`, its optional
observer uses the same original SQL, body/hash verification, complete cursor EOF
and returned sorting. It retains bounded identity/hash metadata for the latest
turn, with at most 32,768 nonheld candidates and 256 characters per identity.
It does not run another query or preserve economic bodies. Held rows are counted
as excluded from this nonheld inventory, never as protected or financially zero.
Overflow, malformed metadata, incomplete iteration and contention make only the
measurement UNKNOWN; original native rows and errors remain authoritative.

Original horizon retirement and watch-due filtering feed separate counts.
Original queue eligibility, actual bounded history-batch requests, actual issued
expensive evaluations and eligible-but-unselected inputs are distinct. Inventory
turns do not create an evaluation obligation for every candidate or trade. A new
turn replaces the latest inventory summary; it does not manufacture another
pending qualification for unchanged unselected work. Inventory snapshots are not
a sealed boot prefix, continuous source cohort or successful evaluation census.

Only the unchanged native one-expensive-work-per-turn branch, after the real
durable `qualification_turn()`, issues an evaluation request. Its identity binds
the actual private Pons owner, candidate, graduation, native qualification
attempt, current native input body hash and observed source-domain frontier.
Only the matching original `_publish_qualification()` final History save can
record `DECISION_COMMITTED`. Plane publication, Attempts, nonfinancial/native
sleeve observation and the original funding admission remain in their original
order. Negative decisions are still decisions; positive admission remains
independent and the isolated native path still denies funding after publication.

Autocommit saves publish after their original SQL returns. Saves within an
actual PonsHistory transaction stage fixed metadata through the existing typed
observer frames; nested SAVEPOINT release cannot publish before the outer
COMMIT. Rollback or failed COMMIT leaves the request unsettled. PostCOMMIT
observer failures never retry, roll back or change the committed native result.
A different later qualification attempt cannot settle an older issued request.
Failed selected requests remain explicit debt; the common reducer's original
eight-active/32,768-unit/eight-MiB bounds refuse overflow rather than drop it.
