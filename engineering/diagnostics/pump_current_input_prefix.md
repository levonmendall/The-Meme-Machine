# Current inherited and newly issued input prefixes

This is an isolated successor of Current stage component `68108818`. It is not
part of the installed performance candidate and grants no readiness, recovery,
historical completion or funding authority. The private boot-support/owner IPC
producer is a separate required dependency. A descriptor dictionary cannot issue
that private capability.

The actual normal boot producer derives the source database identity/schema and
three program upper cuts inside the original verified query-only prewrite
snapshots and held fences, before closing those reads or starting writers. The
consumer requires the actual accepted distinct Pump context and exact typed
private support. It compares original root-record/certificate, application,
financial epoch and source-native input association. Old canonical rows are
inherited support, not newly acquired source economics.

The source outbox is append-only under the reviewed exact native writer and
original exclusive ownership/cutover rules. Runtime `_queue_events` inserts;
source maintenance/archival preserves its metadata. Supported original admin
recovery invokes the original source/publisher only at the stopped fence. This
is an explicit trusted-code/owner premise, not database-enforced immutability or
a defense against arbitrary malicious raw SQL. The consumer rechecks its private
owner, fixed outbox table/index schema and original source-file device/inode;
same inode or MAX sequence alone is not a membership census.

An opt-in independent key-only census seeks the original `(scope,sequence)`
index through the fixed inherited cut. It fetches at most 5,000 keys plus one
lookahead, byte-guards text before materialization and retains completed metadata
prefixes across 25ms leases. It does not replace an existing progress handler or
hold a SQL snapshot across calls. True EOF differs from lookahead, lease expiry
and cancellation. Every cursor closes before decode/yield/retention. Future
availability remains in the expected inherited population; missing or dangling
native payload cannot disappear from a smaller completed census.

The existing Current payload read is unchanged. Inside that same original read
transaction, the actual private-context path adds one fixed, byte-bounded
16KiB-primary-key source-frontier read, one fixed table/index-schema read and one
bounded metadata key seek. No extra transaction, provider operation, per-row
query or second payload scan is added. Legacy/no-private-context paths add none
of these queries. Detached captures advance the retained tuple chain only after
the original FULL history retention returns with its whole row count and neither
source nor consumer transaction remains open.

Both sides use the exact original five-tuple `(sequence, identity, scope, slot,
first_seen)` and per-row `SHA256(canonical([previous_sha, tuple]))`, initially
64 zeroes. SQLite REAL availability is preserved; integers and floats are not
silently rewritten to make a digest match. Program gaps from other source
families are valid. Source and consumer batch partitions do not change a chain.
The new generation's atomic program prefix must begin at the authentic support
cut; it cannot omit intervening native input or relabel restored rows. Exact
physical replay is counted separately. A new-generation issuance prefix is not
the independently closed whole-program economic-arrival census.

Only complete key EOF supplies the inherited expected count/digest. Prefix
retention is separate from complete Current policy/evaluation outcomes. Old
queued generations, postgraduation work, Survivor, held protection and Pons stay
independent applicable populations. Matching an input prefix cannot settle those
jobs. Public projections retain fixed counts/hash/cut/clock fields only and never
become a positive normal-boot witness. Optional stage samples can be explicitly
omitted to preserve the original 16KiB Current envelope; full counts/digests and
omission counts remain, with UNKNOWN if the envelope still does not fit.

Initial pure/real-SQLite proof: twelve cases passed in 0.255s, including a real
5,001-key indexed traversal, lookahead/EOF, expiry/resumption, preservation of the
original SQL progress handler, cancellation/cursor cleanup, future availability,
crossed generation/cuts, replay and missing-tail/schema negatives. The first run
retained three fixture hash failures caused by integer expected availability
versus actual SQLite REAL values; the fixture was corrected to the original
source's SQL-returned tuple contract without changing production serialization.
Logs are `pump-current-input-prefix-key-census-{first,corrected}.log` under
`/workspace/recovery-evidence`; original failure scratch is
`/tmp/mm-engineering-jf9a0t2h`.

After wiring, the common/Current/prefix bundle passed 35 cases in 1.794s without
skips (`pump-current-input-prefix-wired-no-context.log`), including exact original
default/no-private-context SQL, events, cursor, provider and transaction parity.
Actual private IPC composition, native large replay/queued-generation proof and
matched key-scan overhead remain required before this component's final freeze.
No private/native/full-market conformance is claimed by these initial receipts.
