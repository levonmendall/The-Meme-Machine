# Dormant native book and financial-cut links

This first native leaf observes original book membership and per-member versions
on an existing private Pump or Pons owner. It does not implement a complete held
population, protection outcome, held restart, readiness or funding permit. No
application caller selects the observer by default. Original flat read ports,
certificates, reducers, grants, quotes, risk, deadlines and historical unknowns
remain unchanged.

## Actual source seams

The opt-in `held_population` constructor value must come from
`_NativePopulationCapture(private_owner, deadline=..., cancelled=...).book()`.
The owner is the existing exact private `NativePumpOwnerContext` or distinct
`NativePonsOwnerContext`, never its public identity dictionary. The local
collection binds creating PID/thread and its original absolute caller lease;
each native book binds the real owned connection, original full genesis,
known policy, fixed configured path and its observed device/inode metadata.
This associates the original handle under the approved exclusive-owner/no-path-
replacement premise. It is not a retained kernel DB descriptor or independently
complete live physical census.

Pump Current reuses Survivor PaperBook's actual `_record` and `replay` methods.
The shared seam captures the latest verified native journal tuple for each
position from the original successful startup replay, after its original
projection and accounting comparison. It adds no second journal/history scan.
Current's distinct transaction and Survivor's transaction each publish touched
records only after their actual outer COMMIT returns, before original global
flush. Rollback discards metadata only after the actual native ROLLBACK. A failed
or uncertain COMMIT/cleanup keeps the observation incomplete; ordinary observer
failure preserves the original native result or exception. An active original
transaction cannot issue an observed book cut, even before its first record is
staged. Observer errors discard their input traceback frames; original native
exceptions retain their original traceback and cleanup behavior.

Pons Current uses its original `positions()` traversal, verified per-lifecycle
event chain and genuine retained prefix events. Its full genesis includes
capital, delay, namespace and financial policy. The exact native event digest
and explicit `position.version` are retained. `_save` stages only its actual
native event; original reserve/resize/advance COMMIT publishes it before global
flush and the separately owned cohort observer. Savepoints, no-op early returns,
cohort observation and sleeve synchronization do not create a fake native
COMMIT. The opt-in Pons setup reads one `PRAGMA database_list` for its actual
Store locator; ordinary setup and command SQL remain unchanged.

Archive-only PaperBook members lacking an actual per-member journal version
remain incomplete. The book's largest head is never substituted for a member's
version. Pons can use its original authenticated per-member retained event.
Terminal members stay in the bounded collection: open/close between observations
cannot silently become an empty lifetime census. This leaf does not prune them
using callback success or local/global delivery counts.

## Bounds and incremental ownership

One local owner collection shares 32 MiB of retained logical ASCII JSON across
all its book genesis, member and staged bodies, with at most 512 books,
32768 members and 64 staged native records. Size is admitted before encoding a
detached copy. Every retained staged version is charged alongside the committed
version, including repeated updates of one member. Overflow latches observation
failure without changing native admission or financial authority. Logical bounds
do not promise exact RSS; existing native input/output ownership is separate.

Startup uses the original replay's already-rebuilt population. Thereafter a
native COMMIT updates at most the 64 touched records; it does not clone/hash the
whole member population per mark. No new SQL connection, writer, pool, provider
call, cross-thread SQLite access or SQL handler is introduced. The original
caller lease applies through encoding, hashing, detach and final publication;
it is never renewed by this observer.

## Two-way join and deliberately missing scope

`join_native_population` requires the genuine private financial prefix from the
original replay anchor and these private captures. It uses that prefix's
bounded advance and lease-bound detached original state. It joins each
`lane:native_id` through the actual `native_aliases`, regime and native request,
then checks the exact `native:<journal_hash>` original delivery or current
`runtime_pending` identity. Financial native sequence is independent of the
PaperBook journal sequence or Pons version. Reserve preparation may already
record a financial native delivery before native COMMIT: a matching pending
record remains `NATIVE_COMMITTED_GLOBAL_PENDING`, never settled or ACK-complete.
These are event/hash, alias, regime and pending-identity links. They do not by
themselves prove full native/global cash, quantity, sleeve or trial parity; the
original independently verified flows retain their authority and the missing
cross-book reconciliations still have to be implemented.

The reverse traversal retains every financial alias, including funded yet
unmaterialized intents and retired/legacy debt. Missing native books/members or
an exact version/delivery mismatch stay unresolved. All nine original financial
pending class counts and original pending bodies are retained unchanged; legacy
native pending remains `UNESTABLISHED`. The fixed summary has no native bodies,
paths, requests or credentials and always reports overall `INCOMPLETE` with
funding/readiness/held-boot false and protection `UNEXERCISED`.

Even matched book links do not supply complete capital/trial membership, both
sleeves, original controller/history/risk memory, paused/legacy guards, the
complete cross-owner native physical/census association, protection/deadline outcomes or a
cross-process root composition. Those missing inputs remain explicit. The
original flat boot certificate cannot serve as a current post-entry census.
The complete flat-boot-to-entry/scale/monitor/exit lifecycle and held protection
remain separate required integration work before any funding/readiness use.

## Validation scope

Focused fixtures use original disposable native/shared books, grants, reducers,
COMMIT and ACK paths. The existing private owner acquisition premise remains
explicitly simulated in offline tests; the host/root seal is not reissued by a
test hash. No protected state, provider, AWS, kernel image, live throughput or
held protection is exercised.

unchanged in the earlier 80-case selection: Pump accounting 6, Pons partial
accounting 6, shared/native capital preparation 31 and Survivor commit/monitor 19.
