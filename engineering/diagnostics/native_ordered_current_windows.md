# Ordered Current observation windows after f944

This is an unselected successor of the reviewed f944 private input-prefix
component. It grants no source completeness, qualified-request completion,
all-four completion, protection, readiness or funding authority. The source
proof for this composed future tree is intentionally not retargeted here.

The optional ordered mode is enabled only after the actual private Pump owner,
its prewrite BootSupport and the same source-generation association compose.
Legacy finite observers, including existing Pons observers, keep their original
8,192-cohort guard and lifetime replay map. No map is reset or cleared.

The actual ordering witness is `candidate_outbox.sequence`. The original source
assigns these keys to unique canonical publications across all three programs;
the normal source registry folds those same tuples in the original transaction.
Inherited and new Pump rows therefore share this namespace. Gaps caused by other
programs are valid. Native history rowids, slots, candidate generations and Pons
sequences are different domains and are not combined with this high-water mark.

Each new Current window requires the exact original cursor chain, its complete
selected membership and frontier, and a strictly greater last outbox sequence.
Its ID hashes the immutable owner/source binding, fixed domain, sequence and
frontier. An exact still-active window can resume; a closed or different older
window cannot reopen even after its summary has been evicted. Ordering proves
replay exclusion, not the completeness of source arrivals or evaluation demand.

Only active debt, the original sixteen-summary ring, cumulative count/hash and
constant issuance frontier remain in the ordered meter. Its closed-ID map stays
empty. Active/member/row/byte limits remain; each active ordered window charges
128 additional logical metadata bytes. Real pending exhaustion still refuses.
Old pending windows accept only their exact original native outcomes and remain
pending through later summary rotations. Higher positions never settle them.

Capture precedes the original read ROLLBACK and native FULL retention. A failed
FULL return leaves the expected window pending and the original cursor unmoved.
An exact retry preserves issuance, membership, cut and clocks, replacing only
ephemeral event handles. The adapter records the actual source snapshot close
before permitting this retry. Earlier committed 64-row chunks are replayed by
the original idempotent writer; measurement earns retention only after the whole
native call returns its matching count with both transactions closed. No SQL,
provider operation or transaction is added to the default path.

A source may publish beyond the unchanged selected batch before its retry. The
fresh snapshot must still validate the same source and fixed cut; only a
monotone expected publication frontier may advance. Newly published rows remain
unconsumed debt. Regressed/equal-count-conflicting metadata or changed selected
membership refuses. Cancellation after the final hash restores only unpublished
transient tokens, so it cannot orphan a legitimate exact retry or create credit.
Final ordered summary hashing precedes a fresh original clock/owner check and
publication; no lease or native deadline is renewed.

The append-only interpretation continues to rely on the reviewed genuine sole
native writer and exclusive cutover premise. It is not database-enforced
immutability or a defense against arbitrary unauthorized raw SQL. The retained
prefix still does not discharge older queued jobs, request/proof generations,
PumpPostgrad, Survivor or held-position work.

The new native fixture uses actual canonical ingestion, anonymous owner IPC,
original full prewrite financial/native replay, source BEGIN/ROLLBACK and native
FULL history transactions. Synthetic storage create rows make the original
native creation filter produce a genuine empty due traversal. One-row windows
use the existing admitted `ConsumerReader.discovery(limit=1)` API without
changing production's 5,000-row default or forcing strategy work per event.
One actual first filtered outcome is published to the optional meter late,
after thousands of genuine later windows; the native outcome itself is not
fabricated or repeated. The fixed virtual lease in this large fixture isolates
key-page/EOF correlation and is not a production 25ms-capacity result.

The matched arms use the same warmed canonical/history workload and source/
owner, with bounded SQL and metadata-hash counters on both arms. This is a
finite native discovery/FULL/filter observer measurement, not a full runner,
provider, all-market or AWS capacity result. The earlier f944 matched finite
branch overhead of 64.6% remains a separate disclosed receipt.
