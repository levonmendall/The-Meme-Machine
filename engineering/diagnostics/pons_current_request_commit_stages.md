The native commit boundaries remain distinct:

- Successful original `Broker.finish()` supplies preparation. Its Plane result
  and watch transactions already returned from their original COMMITs.

  `Attempts.record()` return supply the evaluation disposition. Missing evidence
  or operational categories remain incomplete. A successor generation cannot
  complete an older request.
- Original `save_cohort_checkpoint()` followed by native result consumption
  supplies the work disposition. The checkpoint's last native public row must
  match the request generation and exact committed qualification vector. A
  missing/failed checkpoint, changed vector or consumption alone earns no work

Plane and Attempts transactions cannot successfully nest SQL BEGIN operations;
these native API returns therefore occur after their real outer transaction.

rolling back or changing the native return. The checkpoint hook hashes only the
last bounded public row, not the multi-megabyte cohort body again.

after the prepared result/decision, before qualification publication. A fixed
