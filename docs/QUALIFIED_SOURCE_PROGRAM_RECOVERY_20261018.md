# Qualified failed-generation program recovery

This optional component recovers one finite `program:pump` or
`program:pumpswap` interval from an authenticated failed **new** source
generation. It preserves the failed source census, registry/session rows,
original callback evidence and the two unknown historical handlers. Its
receipt cannot satisfy NORMAL admission, historical completion, all four
native endpoints, current protection or funding authorization.

`operational.qualified_source_program_recovery.detach_qualified_program_run`
accepts the existing private `QualifiedSourceRecoveryTarget` while its
original short read context remains valid. The protected administration
caller must actually own the stopped/apply fences, exact request/source/epoch
binding, cancellation and original absolute recovery clock. The detached run
keeps only bounded metadata, source inode identity and those private caller
callbacks; it retains no SQL connection and cannot be pickled or transferred
between processes or threads. A public dictionary or callback return Boolean
does not establish the caller's protected ownership premise.

Each `check()` opens a fresh original three-database financial/source target
rejoin through that protected caller and requires the original target digest.
The original ten-second read scopes close before network calls, canonical
writes or consumer FULL commits. This differs from extending the short target
lease. The helper deadline is at most the caller's remaining clock and 120
seconds; a 30-second provider-closing reserve remains. No check renews it.

The first selected supported program is deterministic. The original RPC
validates the network and obtains `getSlot(finalized)`. That immutable upper
must cover the retained handler/program/control frontiers and every actual
registry plane's committed `last_slot`, including a crash with no terminal
census. These observations constrain the fresh upper; none proves a
quiescent tail. Unsupported families, missing known lower bounds or a fresh
upper below those observations refuse. Historical Scout account-state
reconstruction stays unavailable.

`prepare`, `advance_page` and `deliver_once` use the existing native request,
job, pagination token, archive normalization and supplement joins, outer
transaction, canonical ingestion, page receipt, consumer FULL, canonical ACK
and proof publication operations. A page transaction verifies its actual
receipt before commit and checks that every unrelated cursor remains
unchanged. The adapter permits cursor writes only around that original page
and revokes cached statement authorization afterward. The original failed
generation, native session/stream evidence and historical health rows are
write-protected after ordinary writer initialization.

The small `qualified_source_program_recovery` table stores one hashed fixed
target per generation/program. Resume uses that same upper, native job,
pagination token and original job deadline. Expired or failed pending jobs
are refused; their status or clock is never refreshed. A legitimate successor
job through the original request/coverage API is a separate missing slice.
Complete retained job receipts can still be checked after their old deadline.

`verify_program_interval` is constructor-free and uses supplied fresh
query-only transactions. It joins the complete bounded original page receipt
population, actual completed job/witness, absence of pending native consumer
work/proof, original consumer FULL receipt including source generation, and
the published canonical interval point. It rechecks the actual private run
after fallible verification. Connection-local length limits are subtractive
and restored. This joins the native writer's durable receipts; it does not
reconstruct provider payloads that the original schema does not retain.

Its `ECONOMIC_INTERVAL_RECOVERED_ONLY` result explicitly leaves whole-generation,
callback, historical, Scout, native endpoint, funding and NORMAL flags false.
The stored economic-predicate observation is not a cleanup certificate. The
administration result separately requires actual writer closure, closed
provider reservations and the original deadline after cleanup.

Tests use real private source IPC/process death, advisory locks, original
financial replay, SQLite transactions and the original archive/FULL/ACK/proof
pipeline. Root/unit/source acquisition, the Cloud-unavailable native time
namespace, storage namespace and provider transport are explicit fixture
premises. A real `os._exit(17)` after page COMMIT tests persisted token/job
resume and OS lock release. No AWS or actual provider is exercised.

The fixed fixture's full three-database rejoins dominate its elapsed cost.
That conservative first bridge is not a production scaling result; a later
incremental original replay anchor needs separately authenticated writer
scope before replacing repeated full replay. Repeated-failure autonomy also
still needs bounded per-generation handler locator storage through the
original teardown migration: the old global bounded handler ledger is not
made unlimited by an interval receipt. Held-position continuation and the
all-four economic/protection composite remain separate required capabilities.

The companion administration component is dormant. Existing source pins,
worker digests, legacy incident selectors, broker permissions and allowlists
are not promoted by this application branch.
