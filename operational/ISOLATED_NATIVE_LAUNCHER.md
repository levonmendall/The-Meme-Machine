The fixed isolated native launcher is a local component with no workflow,
Supervisor, service, broker, provider or deployment call site. It does not grant
allocation authority, settle callbacks, claim historical completion, or prove
market throughput. The existing namespace canary remains a separate fixed API.

`NativeImageApproval` requires an explicit protected-parent authenticator for
detached exact source commit/tree, requirements, every copied application file,
and six fixed dependency versions/wheel/file hashes. No default authenticator
exists. RECORD and image checksums cannot authenticate themselves. The parent
must join its original installed-source and hash-locked dependency evidence;
that live producer is not implemented here. Source reads after initial checks
use immutable approved commit/tree/blob identities, never a moving HEAD. Every
source/dependency payload is compared to an independently authenticated SHA256.

Only tracked application .py/.json/.proto files, capacity .py files and the one
frozen proof contract can enter the application image. Capacity captures, logs,
engineering evidence, financial books and credentials are excluded. Dependencies
are based58 0.1.1, grpcio 1.84.0, protobuf 7.36.2, pysimdjson 7.0.2,
typing_extensions 4.16.0 and websockets 17.1, with the existing administration
wheel SHA256 pins. Only explicit package prefixes are copied; .dist-info,
direct_url metadata, bytecode, .pth files, original site-packages directories and
arbitrary package directory trees are absent. An explicit stdlib extension of the
canary allowlist supports native
asyncio/HTTP/email/importlib requirements. Copied regular files, size/hash records
and a bounded static ELF dependency closure replace original directory binds.

`launch_native` accepts only an admitted current Scratch scope, exact immutable
approval, a connected unnamed Unix STREAM socket and an anonymous read-only facts
pipe. It cannot select a source directory, environment, command or entrypoint.
The only entry is `meme_machine.operational.isolated_native_entry.main()` with no
argv. The fresh -I/-B/-S bootstrap closes host descriptors/cwd, enters private
user/mount/PID/network/IPC namespaces, pivots/detaches the host root, binds only
the copied image read-only and fresh work writable, drops all capability sets,
locks NNP/namespace reentry, and re-execs -I/-B/-S. Private /tmp and /dev/shm
allow real spawn workers. Local Unix sockets work only in the isolated filesystem.

After checking actual SO_TYPE, socket ownership is remapped to FD3; FD4 must be
an actual O_RDONLY anonymous pipe. Result/log pipes are the only other inherited
descriptors. The parent retains credentials and every external provider transport,
original shared budget, governor and admission authority. Source/facts transport
producers remain separate required integration; missing source/facts capabilities
must remain BLOCKED. No copied financial epoch or implicit positive sizing exists.

The child inherits the original protected cgroup CPU360%, MemoryHigh6G/Max7G,
Tasks4096 and FD65536 configuration when actually launched there; this component
does not install or alter cgroups. Parent image admission uses Scratch and fixed
2048-file/256MiB/64MiB-per-file ceilings. Native work remains under the original
300-second readiness,1800-second work and1865-second outer shutdown scope; the
original protected parent must retain the outer fence over image construction
as well as work. This component's process handle separately enforces1865 seconds
after spawn and65 seconds after graceful cancellation. A native PID1 entry must
install its own cooperative TERM handler; the waiting wrapper survives TERM so
PDEATHSIG does not interrupt cleanup. Parent death/KILL still tears down PID1 and
all namespace descendants. Output is drained concurrently into two64KiB bounds.
Poll/reap and process-group signals share one owner lock to avoid numeric PID reuse.

`prove_image` is a separate fixed offline image proof. It creates its own socket,
facts pipe and synthetic external secret/Unix/TCP canaries; it cannot attach to a
provider session. Its only code path imports the four real native runner modules
and real source modules, imports all six dependencies, exercises a two-worker
spawn pool, private Unix traffic and SQLite FULL/WAL, then requests TERM and checks
that durable cleanup finished. Its explicit4096-FD proof fixture is distinct from
the required65536-FD native profile and reports native_resource_profile_verified
=false. The native profile is never reduced to fit a local host. It starts no
native market runner/source and emits
production_equivalent=false, full_market_speed_proven=false and financial_authority
=false. Successful image proof never substitutes for actual native processing,
restoration, original provider accounting, service enforcement or PAPER readiness.

Actual AWS namespace/service enforcement, complete source execution/transport
parity, parent sizing refresh, exact nonsecret production worker configuration,
native graceful drainage and sustained throughput remain unverified here. No
root broker, permission, sysctl, service, signing or provider quota changes are
part of this component.
