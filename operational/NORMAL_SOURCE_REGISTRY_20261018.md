# Native source session and failed-generation inputs

This is a future component following the reviewed `f0ade0ad`/`a35bf694` source
capability. It neither activates NORMAL nor changes the application allowlist,
funding, provider allowances, financial epochs, strategies or original handler
incident pins. The original two unknown historical handlers remain unknown.

The original immutable root seal authenticates the Supervisor, application and
epoch. The actual child PID, provider, session registry and terminal census
retain trusted native-writer provenance; they are not independently root-sealed
assertions of complete child economics.

Only an actual private NativeSourceGeneration enables the registry. It uses the
existing canonical writer, binds that writer's actual thread/path/provider, and
opens each original Yellowstone/WebSocket stream before subscription I/O. Rows
retain actual original stream/session IDs, plane, scopes, lower bound and fixed
subscription digest. There are no URLs, credentials, packets or duplicated
economic payloads. Stopping references the original transport lifetime; joined
teardown references the original acquisition observation by ID and body hash.
Initial/terminal per-program outbox cuts use the original covering
candidate_outbox_scope index. They are native-writer starting metadata, not an
independent root-sealed inherited-work census. A separate private support
boundary must associate the original verified prewrite snapshot before native
consumers may close all inherited obligations.

Generation setup adds one FULL transaction. Each stream adds one opening and
one stopping FULL transaction. The original teardown transaction also retains
its closure reference; it does not add a second commit. Actual frame counters
and frontiers update inside the existing bounded native/scout outer COMMIT.
Outbox metadata similarly shares the original canonical transaction. It adds
no per-row SQL or per-message fsync. No-capability paths create no registry
tables or publication metadata and preserve original SQL and outcomes.

SelectiveHistory._queue_events supplies its original complete newly-inserted
five-tuples `(sequence,identity,scope,slot,first_seen)` immediately after its
unchanged executemany. Existing/replayed identities do not become new work.
The registry retains aggregate and three fixed original FAMILIES program
prefixes, plus the actual active program set. Each ordered tuple advances
`SHA256(canonical([previous_sha256, tuple]))`, starting at 64 zeroes. This is
independent of source/consumer batch partitioning. Original source-batch counts
are descriptive only. An old outbox population preceding initial_frontiers is
not retroactively attributed to this source generation.

The already-existing service_health table exposes the optional key
`source_generation_frontier`. Its exact schema is
`normal-source-publication-frontier-v1`, with fields `schema`,
`identity_sha256`, `generation`, `active_programs`, `economic`, and
`initial_program_outbox_sequence`. The initial cut map has the three exact
program scopes and the actual original upper sequence or null for no row.
`economic.all` and each `economic.programs[program_scope]` contain
`records,batches,first_sequence,last_sequence,prefix_sha256`. The three scopes
are program:meteora, program:pump and program:pumpswap. Readers must join the
immutable generation identity, exact initial cuts/sequence prefix and their
independent expected work population. The actual registry constructor publishes
its zero-issued frontier in its existing transaction, before subscription I/O.
Missing metadata is unavailable, not zero. A source
prefix or history ACK alone proves neither a native decision nor protection.
The pure `validate_publication_frontier` accepts a bounded raw row or decoded
fixed object, validates shape/count/range/program/cut coherence, and returns a
detached value. It authenticates no producer, capability, boot-support census or
economic completion on its own.

`derive_failed_generation_plan(StoppedNativeReadContext)` is a constructor-free
read port. The caller supplies the original authenticated stopped/census/inode
and read-transaction fences; the function opens no arbitrary/native input file,
provider, writer or privileged route. The original provenance verifier does
read the one fixed protected prior root launch record. It verifies root/native producer provenance,
original historical boundary, current census checksum, bounded registry rows
and complete session EOF. It refuses missing/crossed sessions, changed closure
receipts, queue algebra errors and unsupported handler populations. The private
returned plan rechecks its actual owner, deadline, database snapshot and caller
fences before exposing a detached value.

The extractor bounds individual bodies at 16 KiB, sessions at 100,000 and
encoded inputs at 32 MiB, including a conservative 4 MiB reserve for the
original <=64 callback / <=48-gap joins. SQL bounds text before materializing
it. These are encoded-data bounds, not exact Python RSS limits. Original source
census/handler size limits and the caller's outer deadline remain in force.

Known failed callbacks join the original retained HandlerLedger record and
actual native gap/control references. A callback that failed before feed_log
can extend the retained upper beyond the join's completed/buffered slot even
when all accepted queues committed. An undecoded new callback retains only the
registered subscription's potential effect universe. This does not locate or
complete the old unregistered historical callbacks. Actual later control
coverage may clear an acquisition obligation; the old failed callback range
and current remaining obligation stay distinct and require canonical
revalidation. Neither is relabeled returned.

RUNNING is the original initial census, not a live callback census. A crash
therefore retains known later failed rows but explicitly reports an unknown
crash tail. Stream closure, a stopped flag or one observed callback slot never
supplies a quiescent final frontier. A fresh genuinely authenticated upper is
still required. The plan preserves the failed raw census hash/cause, original
unknown count and source state. All recovery, historical completion, normal
readiness and funding flags remain false.

The component does not execute recovery or issue a semantic recovery receipt.
Original canonical replay, complete historical-job/delivery populations,
consumer FULL/ACK, original proof publication, all four native outcomes and
held protection are required subsequent witnesses. The existing prewrite
guard continues to refuse an unresolved new generation; no caller-provided
completed flag, newer head or registry digest bypasses it. Legacy history is
preserved separately from any future fresh scoped cutover.
