# Genuine sizing for the contained native parent

This is an opt-in application component, not an activated administration action
or an operational approval. `LiveNativeParent.run` connects the existing fixed
copied native entry to the existing parent HTTP/native transports and the
existing `ParentSizingProducer`. The child receives detached positive native
sizing facts over FD4 and public provider data over FD3. It receives no provider
credentials, financial database paths, financial constructors, grants or signing
authority. Production state is never opened by this component.

The trusted protected caller must authenticate the exact application/dependency
approval, diagnostic request/unit/source identity and ownership fence. It supplies
`ProtectedFinancialInput(read_financial, validate_scope)`: the first callback
performs the original constructor-free full financial replay once; the second
freshly verifies the unchanged selection/head and exclusive diagnostic owner.
Both execute on the creating parent thread. The existing financial-basis and
native valuation formulas remain authoritative; callbacks and hashes do not
authenticate arbitrary JSON. Full stopped discovery closure is not a sizing
prerequisite. Original flat financial/native obligations and protection predicates
remain prerequisites of the protected caller.

The caller also supplies existing bounded bootstrap `Budget`, Solana `Governor`
and Pons `Admission` objects in the admitted private parent directory. This class
does not create allowance, reset ledgers, import production provider history or
increase quotas. The protected integration must establish the original remaining
allowance, uncertainty/debt, provider history and pacing. The complete native
source registry uses actual configured endpoint identities: six runner/discovery
roles, eighteen source priority/operation roles, two source stream aliases and
three native transports. Separate child and sizing worker lanes share those same
controls. The existing shared-channel capacity-overflow closure is an outstanding
all-four concurrency dependency; more workers are not used to hide it.

`LiveNativeScope` explicitly labels this private `/tmp` allocation
`DISPOSABLE_LIVE_NATIVE_OBSERVATION`. It retains the original engineering
admission, growth and failed-evidence policy, binds the exact diagnose request,
source and unit invocation, and requires a fresh protected fence before launch.
It cannot be accepted by the ordinary offline-scratch launcher path. A one-shot
`PreparedNativeImage` prepares the unchanged pinned image before acquiring the
short-lived genuine USD facts. Original child-side inode/source verification and
the existing fixed Landlock/seccomp launcher remain in place. Default offline
and production paths are unchanged.

The existing native oracle/route/canonical decoders earn each renewal. Pons facts
retain their original five-second validity; SOL retains its original bound. The
parent starts renewal within the old quote's remaining lifetime and refuses
stale acquisition or publication. It never updates timestamps or extends an old
valuation. Packets bind the actual FD3 session, source pair, epoch and original
financial sequence; sending another packet does not increment that sequence.
The parent owns native sizing caches on one thread, translates the original Pump
wall-clock deadline separately from Pons/IPC monotonic deadlines, and closes SQL
only after accepted acquisitions join.

Bounds are 300 seconds of startup, at most 900 seconds of requested work, and the
original single 65-second drain. Independent owners continue draining after an
ordinary cleanup failure. Incomplete cleanup raises `NativeOwnerDrainFailure`,
retains the parent/tasks/original cause, and prevents host-fence release. A lost
fence at scope exit restores temporary-directory globals and retains evidence.
The external service stop remains containment, not proof of graceful shutdown.

Focused offline tests use a real replayed synthetic $1,000 epoch, original native
USD readers and Budget/Governor/Admission, actual socketpairs and FD4 consumption,
positive native basis, genuine renewal and joined cancellation. Provider replies
are fixed offline fixtures. The small test child exercises resource/fact transport,
not all four native market loops. Earlier failures remain retained: the Pump
wall/monotonic adapter mismatch was corrected; a renewal fixture child exited
without a terminal receipt before its stop handler was corrected. That first
renewal verdict remains FAIL with its original cause unproved.

There is no claim here of live provider acquisition, kernel application, all-four
economic processing, sustained capacity, historical recovery, normal readiness
or one-hour acceptance. Genuine LIVE-scope execution under the actual kernel and
service identity, independently authenticated source/dependencies, protected admin
embedding, shared-channel backpressure and the separately reviewed Pons native
owner lifetime remain integration dependencies. No broker action, permission,
approval manifest or deployed source is changed by this component.
