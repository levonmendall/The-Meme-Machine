# Explicit bookless native runner component

This component is local engineering work. It does not install a runtime, source
worker, credential route, financial epoch or readiness exemption.

`NativeRunnerPorts(resources, ChildChannel)` exposes only fixed parent-issued read
roles. Pump RPC sessions retain the actual native immutable-read and broker caches
in one private SQLite file. Pons sessions retain the actual native immutable
EvidenceStore. Nested concentration and postgraduation scan clients propagate the
same explicit port and caches while keeping their original logical budgets.
Missing roles, source files and unsupported stream capabilities fail closed.

Pump Current's actual `runner.main` accepts explicit resources/ports. It validates
its fixed private report, candidate-history, evidence and broker paths before any
open. Its actual pipeline, candidate restoration, acquisition/qualification loop,
candidate persistence and post-publication allocation denial remain in place.
No PaperBook or monetary recovery is constructed. Every qualification call
receives the explicit resource capability; a private pipeline is accepted only
when bound to the actual owner context. An existing unrelated pipeline remains a
refusal. The existing production default and financial startup are retained.

Both actual Survivor Runtime constructors now accept explicit resources/ports,
require `capital=None`, bind the authenticated scope and own real History,
CandidateHistory, observation sleeve and Evidence/Plane objects. Their actual
steps keep native discovery, history reduction, qualification and durable denial.
An unexpected position, reservation or pending financial action stops before
provider work and is preserved. No financial state is manufactured or cleared.
History handles are released on the native worker thread; a subsequent owned
runtime can reopen the same verified private inode. Failed constructors also
release their partial owners on that thread. Worker construction/steps enter the
explicit denial-only financial context. Production defaults remain unchanged.

The reports state `financial_authority=false`; financial reconciliation, replay,
held protection, fills and settlement are `UNEXERCISED`. Financial durable handoff
is false. Actual nonfinancial observation verification remains separately visible.
Fresh sizing facts are mandatory; this component does not extend a valuation's
original lifetime or create a positive book as a sizing source.

Focused offline evidence includes actual Current startup, candidate restoration
and cancellation; both actual Survivor constructors/worker prime/close; native
history restart; failed-constructor cleanup; stale sizing and unexpected financial
continuation refusal; actual positive Current qualification followed by pipeline,
decision and funding-denial persistence. Physical transports are offline doubles
behind real disposable parent Budget/Governor/Admission controls. No live market,
source throughput or held-position claim follows from those tests.

Still required: actual authenticated source-owner/ProcessPool/FULL-delivery and
consumer-ACK integration, opaque concurrent native streams, Nitro feed injection,
the genuine protected-parent sizing producer/refresh, strict copied-image OS
execution, recorded-corpus parity and bounded AWS validation. Pons Current's full
bookless loop is a separate coordinated component. The current port's Nitro
method explicitly refuses instead of substituting a clock or public sampler.
